# learning-ai-agents

Учебный проект по разработке простого ИИ-помощника на Python. Проект постепенно
развивается от отдельных упражнений до чата, который помнит историю переписки,
проверяет доступ к API и использует актуальную погоду в Красноярске.

Проект использует только стандартную библиотеку Python. Внешние зависимости не
нужны: запросы выполняются через `urllib`, JSON разбирается через `json`, тесты
написаны на `unittest`.

## Требования

- Python 3.14 или новее (см. `pyproject.toml`);
- доступ к API NeuralDeep;
- желательно `uv` для управления виртуальным окружением;
- для погоды — доступ к `air.krasn.ru`;
- для резервного источника — доступ к `api.open-meteo.com`.

## Переменные окружения

`lesson-0/main.py` и `lesson-3/ex4.py` читают файл `.env` в корне проекта.
Код устроен просто:

1. читает файл целиком;
2. убирает пробелы и переносы по краям;
3. делит строку по первому `=`;
4. кладёт имя и значение в `os.environ`;
5. использует значение как Bearer-токен для NeuralDeep.

Поэтому `.env` должен содержать **одну строку**:

```text
NEURALDEEP_API_KEY=ваш_токен
```

Имя переменной может быть любым, но оно должно совпадать с тем, что вы указали
в файле. Значение не должно содержать переводов строк. `.env` уже добавлен в
`.gitignore` и не должен попадать в git.

### lesson-3 — помощник с погодой

Основной и самый полный пример проекта. Чат:

- загружает историю переписки из `history_chat.json`;
- получает погоду при старте;
- добавляет погоду в **системный промпт**, а не в каждое сообщение пользователя;
- отправляет сообщения в NeuralDeep;
- сохраняет историю после успешного ответа;
- проверяет доступ к API через `netcheck.py`.

#### Файлы `lesson-3`

| Файл | Назначение |
|---|---|
| `ex4.py` | чат, системный промпт, история, вывод погоды |
| `weather.py` | получение погоды, единый формат, проверка свежести, резервный источник |
| `netcheck.py` | проверка API NeuralDeep и объяснение проблем с VPN/TUN |
| `test_lesson3.py` | тесты погоды и структуры сообщений без реальной сети |
| `history_chat.json` | сохранённая история переписки |

#### Как проходит один запуск

1. `get_weather()` получает погоду из `weather.py`.
2. `format_weather()` превращает словарь в понятный текст.
3. `load_history()` читает историю, `build_messages()` оставляет только
   корректные сообщения `user`/`assistant` и добавляет один системный промпт.
4. `ensure_api()` проверяет доступ к NeuralDeep.
5. В цикле пользователь вводит текст, сообщение добавляется как
   `{"role": "user", "content": "..."}`.
6. Ответ модели добавляется как `{"role": "assistant", "content": "..."}`.
7. История сохраняется только после успешного ответа.

## Погода в `lesson-3`

### Основной источник: air.krasn.ru

Сейчас в `weather.py` выбрана станция:

```text
ID:    4228
Имя:   о. Татышев
Сеть:  КНЦ СО РАН (project 9)
```

Публичный API не требует ключа:

```text
GET https://air.krasn.ru/api/2.0/projects
GET https://air.krasn.ru/api/2.0/projects/9
GET https://air.krasn.ru/api/2.0/data
```

Параметры `/api/2.0/data`:

| Параметр | Значение |
|---|---|
| `time_begin` | начало периода, `YYYY-MM-DD HH:mm:ss` |
| `time_end` | конец периода, `YYYY-MM-DD HH:mm:ss` |
| `time_interval` | `hour`, `day` или `month` |
| `sites` | ID станции; можно несколько через запятую |

Пример запроса (даты нужно подставить актуальные):

```bash
curl -sS -m 15 \
  "https://air.krasn.ru/api/2.0/data?time_begin=2026-11-13%2016:00:00&time_end=2026-11-13%2019:00:00&time_interval=hour&sites=4228"
```

Ответ содержит обёртку со статусом и массив `data`. Ниже — пример структуры,
значения условные:

```json
{
  "status": {"code": 1, "message": "OK"},
  "data": [
    {
      "time": "2026-11-13 18:00:00",
      "site": 4228,
      "t": -0.1,
      "p": 751.2,
      "h": 73,
      "aqi": 39,
      "iaqi": 39,
      "pm25": 7.0,
      "pm10": 7.6,
      "pm25_mcp": 0.2
    }
  ]
}
```

Поля API:

| Поле | Смысл | Единица |
|---|---|---|
| `time` | время измерения (часовой агрегат) | локальное время Красноярска |
| `site` | ID станции | — |
| `t` | температура воздуха | °C |
| `p` | атмосферное давление | мм рт. ст. |
| `h` | относительная влажность | % |
| `pm25` | концентрация PM2.5 | мкг/м³ |
| `pm10` | концентрация PM10 | мкг/м³ |
| `aqi` | обычный AQI | безразмерный |
| `iaqi` | Instant AQI, оперативный индекс | безразмерный |
| `pm25_mcp` | доля среднесуточного ПДК | безразмерная |

`status.code = 1` означает успех. Отрицательный код — ошибка API.

Публичный API 2.0 отдаёт **почасовые агрегаты**. Это не сырые мгновенные
показания датчика, а значение с меткой `HH:00:00`. Для проверки актуальности
этого достаточно, но нужно помнить, что данные могут отставать от реального
времени.

В публичном API 2.0 **нет скорости ветра**. Внутренний endpoint сайта
`sensor.krasn.ru` иногда содержит `wv`/`wd`, но он не является официальным
публичным API и не содержит PM10. Поэтому в текущей версии ветер у основной
станции обычно попадает в список недоступных показателей.

### Резервный источник: Open-Meteo

Если air.krasn.ru недоступен, вернул пустые/битые данные или данные старше
двух часов, `weather.py` пробует Open-Meteo:

```text
https://api.open-meteo.com/v1/forecast
  ?latitude=56.0184
  &longitude=92.8672
  &current=temperature_2m,relative_humidity_2m,wind_speed_10m,surface_pressure
  &wind_speed_unit=ms
  &timezone=Asia/Krasnoyarsk
```

Open-Meteo — это **расчётные данные модели**, а не измерения станции. Поэтому
в результате ставится `data_type: "model"`, а в тексте для модели явно
пишется «расчётные данные модели Open-Meteo».

Open-Meteo в этом запросе не даёт PM2.5, PM10 и AQI. Эти показатели честно
попадают в `missing` и не выдумываются.

Давление Open-Meteo приходит в гПа и пересчитывается в мм рт. ст.:

```text
мм рт. ст. = гПа × 0.750061683
```

### Единый формат результата

`get_weather()` возвращает словарь или `None`. Пример структуры (значения
условные):

```json
{
  "source": "air.krasn.ru (сеть мониторинга КНЦ СО РАН)",
  "source_url": "https://air.krasn.ru/",
  "station": "о. Татышев",
  "station_id": 4228,
  "measured_at": "2026-11-13 18:00:00",
  "data_type": "measurement",
  "aggregation": "hourly",
  "temperature_c": -0.1,
  "humidity_pct": 73.0,
  "pressure_mmhg": 751.2,
  "pm25_ugm3": 7.0,
  "pm10_ugm3": 7.6,
  "aqi": 39.0,
  "aqi_type": "Instant AQI",
  "wind_speed_ms": null,
  "is_stale": false,
  "stale_reason": null,
  "missing": ["wind_speed_ms"]
}
```

| Ключ | Смысл |
|---|---|
| `source` | название источника |
| `source_url` | ссылка на источник |
| `station` | название станции |
| `station_id` | ID станции или `null` |
| `measured_at` | время измерения |
| `data_type` | `measurement` — измерение, `model` — расчёт модели |
| `aggregation` | `hourly` — часовой агрегат, `current` — текущие данные модели |
| `temperature_c` | температура, °C |
| `humidity_pct` | влажность, % |
| `pressure_mmhg` | давление, мм рт. ст. |
| `pm25_ugm3` | PM2.5, мкг/м³ |
| `pm10_ugm3` | PM10, мкг/м³ |
| `aqi` | индекс качества воздуха |
| `aqi_type` | `Instant AQI` или `AQI (усреднённый)` |
| `wind_speed_ms` | скорость ветра, м/с |
| `is_stale` | `true`, если данные устарели |
| `stale_reason` | причина устаревания |
| `missing` | список ключей, которых нет в ответе |

`None` означает, что показатель недоступен. Это не ноль и не выдуманное
значение.

### Как выбирается источник

```text
1. Запросить air.krasn.ru.
2. Если ответ корректный и свежий — вернуть его.
3. Если основной источник упал/пустой/битый/устаревший — запросить Open-Meteo.
4. Если Open-Meteo дал свежие данные — вернуть их с пометкой model.
5. Если резерв недоступен, но есть устаревшие измерения станции —
   вернуть их с is_stale = true и причиной.
6. Если нет ничего — вернуть None.
```

Повторных запросов нет. Таймаут одного HTTP-запроса — 10 секунд.

### Проверка свежести

- Время API считается временем Красноярска (UTC+7).
- Данные старше 2 часов считаются устаревшими.
- Отсутствие времени — ошибка проверки актуальности.
- Время, которое заметно опережает текущее, тоже считается подозрительным.

Если данные устарели, в системном промпте появляется предупреждение,
а модель обязана сказать об этом пользователю.

### Отладка `weather.py`

В начале `weather.py` есть переключатель:

```python
DEBUG_MODE = False
```

Если поставить `True`, программа будет печатать выбранный источник, станцию,
время измерения, причину устаревания и ошибки обоих источников. В обычном
режиме эти сообщения не мешают чату.

### Как сменить станцию

1. Получите список станций:

   ```bash
   curl -sS -m 15 "https://air.krasn.ru/api/2.0/projects/9"
   ```

2. Выберите `id` и `name` станции.
3. Измените в `lesson-3/weather.py`:

   ```python
   KRASN_STATION_ID = 4228
   KRASN_STATION_NAME = "о. Татышев"
   ```

4. Проверьте, какие поля реально приходят:

   ```bash
   cd lesson-3
   python3 -c "from weather import get_weather; import pprint; pprint.pp(get_weather())"
   ```

5. Если у станции нет части показателей, они попадут в `missing` — это
   нормально и не является ошибкой.

Тесты используют константы `KRASN_STATION_ID` и `KRASN_STATION_NAME`, поэтому
после смены станции их не нужно переписывать вручную.

## Возможные проблемы

### Нет файла `.env`

Будет ошибка `FileNotFoundError` при открытии `.env`. Создайте файл в корне
проекта с одной строкой `NAME=VALUE`.

### `.env` содержит несколько строк

Код рассчитан на одну строку. Если строк несколько, имя и значение могут
разобраться неправильно. Оставьте только `NAME=VALUE`.

### Ошибка SSL `UNEXPECTED_EOF_WHILE_READING`

Обычно это VPN в режиме TUN (например, Happ), который перехватывает трафик до
`api.neuraldeep.ru`. `netcheck.py` проверяет API, объясняет причину и может
предложить добавить маршрут в обход VPN. На Windows для этого потребуется
подтвердить UAC. Не меняйте маршруты и настройки VPN, если не понимаете, что
делаете.

### air.krasn.ru недоступен

Проверьте адрес вручную:

```bash
curl -sS -m 15 "https://air.krasn.ru/api/2.0/projects"
```

Если основной источник недоступен, программа автоматически пробует
Open-Meteo. Если и он недоступен, `get_weather()` вернёт `None`, а чат получит
инструкцию не выдумывать погоду.

### Open-Meteo отвечает таймаутом

В некоторых сетях Open-Meteo недоступен без VPN. Это не ломает программу:
если air.krasn.ru работает, резервный запрос вообще не выполняется. Если
основной источник упал, программа подождёт до 10 секунд и вернёт `None` или
устаревшие данные станции с предупреждением.

### Станция показывает странные значения

Код проверяет наличие полей и свежесть времени, но **не проверяет физическую
правдоподобность** значений. Если датчик неисправен или передаёт ошибку,
программа покажет то, что пришло от API, и не будет придумывать «нормальное»
значение. В таком случае выберите другую станцию через
`KRASN_STATION_ID`/`KRASN_STATION_NAME`.

### Нет скорости ветра

Публичный API air.krasn.ru 2.0 не отдаёт ветер. Это ожидаемо: показатель
попадает в `missing`, а в тексте появляется «Недоступны: Скорость ветра».
Ветер есть только у резервного Open-Meteo.

### Повреждена история переписки

`load_history()` проверяет, что файл содержит список. Неправильные элементы
(например, строка вместо словаря) отбрасываются. Файл перезаписывается только
после успешного ответа модели. Если история нужна, сделайте резервную копию
перед экспериментами.

## Ограничения проекта

- air.krasn.ru отдаёт почасовые агрегаты, а не мгновенные сырые измерения;
- используется одна станция, данные разных станций не смешиваются;
- через публичный API air.krasn.ru скорость ветра основной станции недоступна;
- Open-Meteo не даёт PM2.5, PM10 и AQI;
- нет проверки физических диапазонов значений;
- нет tool calling, Telegram-бота и базы данных;
- чат зависит от доступности NeuralDeep;
- история переписки хранится в JSON и не ограничена по размеру.
